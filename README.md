# POS Multi-Store (โปรเจ็คใหม่)

โปรเจ็คนี้แยกจากระบบ POS_Water_Database เดิมทั้งหมด — ไฟล์ใหม่, Google Sheet ใหม่, ไม่แตะไฟล์เก่าใดๆ

**Google Sheet ใหม่:** `POS_MultiStore_Database`
https://docs.google.com/spreadsheets/d/1S2AXBIOSbLNGOUU3kD23H6j-ZP0ttsou8kDkSOkuFcA/edit

## โครงสร้างไฟล์

- `index.html`, `style.css`, `app.js` — หน้าเว็บ (Static Web App, ไม่ต้องมี server)
- `Code.gs` — สคริปต์ฝั่งหลังบ้าน (วางใน Apps Script ของ Google Sheet ใหม่)

## ขั้นตอนติดตั้ง (ทำครั้งเดียว)

1. เปิด Google Sheet ที่ลิงก์ด้านบน
2. เมนู **ส่วนขยาย (Extensions) > Apps Script**
3. ลบโค้ดตัวอย่างเดิมทิ้ง แล้ววางโค้ดทั้งหมดจากไฟล์ `Code.gs`
4. ที่แถบด้านบน เลือกฟังก์ชัน `setup` แล้วกด **Run** (ครั้งแรกจะขอสิทธิ์ — กดอนุญาต) ขั้นตอนนี้จะสร้างชีตย่อยทั้งหมดพร้อมข้อมูลตั้งต้น:
   - `Stores` — ร้านค้า (ผู้ชายขายน้ำ, นาแบะโอนลี่)
   - `Users` — ผู้ใช้งาน (จดจำจาก Client ID อัตโนมัติ)
   - `Inventory` — สินค้าของแต่ละร้าน
   - `Couriers` — ผู้จัดส่ง (ไนซ์, เอฟ, เทพ)
   - `Settings` — ค่าคอนฟิกที่แก้ได้เองในชีต เช่น `courier_commission_rate` (% ค่าคอมมิชชั่นคนส่ง)
   - `Customers` — ทำเนียบลูกค้า (ชื่อ/เบอร์/ที่อยู่/หมายเหตุ) ใช้โดยช่องค้นหาลูกค้าตอนบันทึกออเดอร์
   - `Orders_shop_a`, `Orders_shop_b` — ออเดอร์ของแต่ละร้าน **แยกชีตกันคนละแท็บ** ไม่ปนกัน (ถ้าเพิ่มร้านใหม่ในแท็บ Stores ระบบจะสร้างแท็บ `Orders_<store_id>` ให้อัตโนมัติตอนมีออเดอร์แรกเข้ามา)
5. เมนู **Deploy > New deployment**
   - Type: **Web app**
   - Execute as: **Me**
   - Who has access: **Anyone**
   - กด Deploy แล้วคัดลอก **Web app URL**
6. เปิดไฟล์ `app.js` แก้บรรทัด:
   ```js
   const GAS_URL = 'https://script.google.com/macros/s/PASTE_YOUR_DEPLOYMENT_ID_HERE/exec';
   ```
   วาง URL ที่คัดลอกมาแทนที่
7. เปิดไฟล์ `index.html` ในเบราว์เซอร์ (หรือ deploy ทั้งโฟลเดอร์ขึ้น GitHub Pages / Netlify เพื่อให้ใช้งานได้จากมือถือ)

> ทุกครั้งที่แก้โค้ดใน Apps Script แล้วอยาก deploy URL เดิม ให้ใช้ **Deploy > Manage deployments > แก้ไข (ดินสอ) > Version: New > Deploy** — จะไม่ต้องแก้ GAS_URL ใน app.js ใหม่

## วิธีทำงานของระบบ

**หน้า A — ระบุตัวตน + เลือกร้าน**
เมื่อเปิดเว็บครั้งแรกในเบราว์เซอร์นั้น ระบบจะสร้าง Client ID แบบสุ่มเก็บไว้ใน `localStorage` ของเครื่อง/เบราว์เซอร์นั้น แล้วให้กรอกชื่อครั้งเดียว จากนั้นทุกครั้งที่เปิดใช้งาน ระบบจะจำชื่อ/สิทธิ์ (Permission) ได้อัตโนมัติจาก Client ID โดยไม่ต้องล็อกอินใหม่ ถัดมาเลือกร้านที่จะเข้าไปจัดการ (โลโก้วงกลม + ชื่อร้าน)

**หน้า B — บันทึกออเดอร์**
แสดงสินค้าของร้านที่เลือกเป็นตาราง กดที่สินค้าหรือปุ่ม +/− เพื่อเพิ่ม-ลดจำนวนได้อิสระทีละรายการ มีสรุปรายการ + ยอดรวมด้านล่าง กด **บันทึกส่งออเดอร์** จะเด้ง popup ให้เลือกผู้จัดส่ง (ไนซ์ / เอฟ / เทพ) เมื่อเลือกแล้วออเดอร์จะถูกส่งไปบันทึกในแท็บ `Orders_<store_id>` ของร้านนั้นๆ ทันที (เช่นออเดอร์ร้านผู้ชายขายน้ำเข้า `Orders_shop_a` ส่วนนาแบะโอนลี่เข้า `Orders_shop_b` แยกกันเด็ดขาด)

> ถ้าเคยรัน `setup` เวอร์ชันเก่าไปแล้วและมีแท็บ `Orders` แบบรวมเดียวที่มีข้อมูลอยู่ (ไม่ใช่แค่หัวตาราง) โค้ดใหม่จะไม่ลบแท็บนั้นให้อัตโนมัติ — ให้แยกแถวตาม `store_id` ไปวางในแท็บ `Orders_shop_a` / `Orders_shop_b` เอง แล้วค่อยลบแท็บ `Orders` เดิมทิ้ง

**หน้า C — ประวัติออเดอร์ (History Orders)**
บนหน้าบันทึกออเดอร์มีปุ่ม **🧾 ประวัติ** มุมขวาบน กดเข้าไปจะเห็นออเดอร์ล่าสุด 100 รายการของร้านนั้น (อ่านสดจากแท็บ `Orders_<store_id>` โดยตรง) ไม่ต้องเปิด Google Sheet อีกต่อไป:

- สลับดู **ทั้งหมด / ของฉัน** (ของฉัน = ที่บันทึกจากเครื่องนี้)
- สรุปหัวหน้าจอ: จำนวนออเดอร์วันนี้ + ยอดรวมวันนี้ (ไม่นับที่ยกเลิก)
- แตะการ์ดออเดอร์เพื่อดูรายละเอียดสินค้าทีละชิ้น + ราคาต่อบรรทัด + เลขที่ออเดอร์
- ปุ่ม **ยกเลิกออเดอร์นี้** สำหรับออเดอร์ที่กดผิด — **ไม่ลบแถวในชีต** แต่เปลี่ยน `status` เป็น `ยกเลิก` และตั้ง `commission_paid` เป็น TRUE เพื่อไม่ให้ถูกนับเป็นยอดขายหรือค่าส่งอีก (ประวัติยังอยู่ครบสำหรับตรวจสอบย้อนหลัง)
- ปุ่ม **⟳** โหลดใหม่

**ยืนยันการบันทึก (แก้ปัญหา "กดบันทึกแล้วไม่รู้ว่าสำเร็จไหม")**
หลังเลือกคนส่ง ปุ่มจะเปลี่ยนเป็น "กำลังบันทึก..." แล้วเด้งกล่องผลลัพธ์ชัดเจน:

- **สำเร็จ** — ติ๊กถูกสีเขียว พร้อมยอดรวม / คนส่ง / เวลา / เลขที่ออเดอร์ที่เข้าชีตจริง และปุ่มลัด "ดูประวัติออเดอร์"
- **ไม่สำเร็จ** — กากบาทสีแดง บอกสาเหตุ ของในตะกร้ายังอยู่ครบ และมีปุ่ม "ลองบันทึกอีกครั้ง"
- การกดลองใหม่ **ไม่ทำให้เกิดออเดอร์ซ้ำ** — แต่ละครั้งที่กดบันทึกจะแนบรหัส `client_uid` ไปด้วย ถ้าเน็ตหลุดหลังจากที่แถวถูกเขียนลงชีตไปแล้ว การกดใหม่จะเจอรหัสเดิมและรายงานว่า "ออเดอร์นี้บันทึกไว้แล้ว" แทนการเขียนซ้ำ

> **ถ้าเคยติดตั้งไปก่อนหน้านี้:** เปิด Apps Script แล้วรันฟังก์ชัน `migrateClientUidColumn` หนึ่งครั้ง (เพิ่มคอลัมน์ `client_uid` ให้แท็บ `Orders_*` เดิม) จากนั้น **Deploy > Manage deployments > แก้ไข > Version: New > Deploy**

## ติดตั้งเป็นแอป (PWA) บนมือถือ

โปรเจ็คนี้ตั้งค่าให้เป็น PWA (Progressive Web App) แล้ว — เปิดครั้งแรกผ่านเบราว์เซอร์ แล้ว "Add to Home Screen" จะได้ไอคอนบนหน้าจอ เปิดแล้วเต็มจอแบบแอปจริง ไม่มีแถบ URL ของเบราว์เซอร์ให้เห็น:

- **iPhone (Safari):** เปิดเว็บ > กดปุ่ม Share (สี่เหลี่ยมมีลูกศรชี้ขึ้น) > เลื่อนหา **"Add to Home Screen"** > กด Add
- **Android (Chrome):** เปิดเว็บ > จะมีแบนเนอร์ "Install app" เด้งขึ้นมาเอง หรือกดเมนู 3 จุดมุมขวาบน > **"Install app"** / **"Add to Home screen"**

ไฟล์ที่เกี่ยวข้อง: `manifest.json` (ชื่อแอป/ไอคอน/สี), โฟลเดอร์ `icons/` (ไอคอนแอป), `sw.js` (service worker ทำให้เปิดแอปได้เร็วขึ้นและติดตั้งได้ — ไม่ cache การเรียก Google Sheet ข้อมูลออเดอร์ยังสดใหม่เสมอ) ต้องอัพขึ้น GitHub พร้อมกับไฟล์อื่นๆ ทั้งหมดด้วย (รวมทั้งโฟลเดอร์ `icons/`)

## แก้ไข/เพิ่มร้านหรือสินค้า

แก้ไขได้ตรงในแท็บ `Stores` และ `Inventory` ของ Google Sheet ได้เลย ไม่ต้องแก้โค้ด — เว็บจะดึงข้อมูลสดจากชีตทุกครั้งที่เปิดหน้า (ตั้ง `active` เป็น FALSE เพื่อซ่อนแถวโดยไม่ต้องลบ)

## โปรฯ ราคาเหมา (Bundle Pricing) — Ammarit 40.- ครบ 3 = 110.-

แท็บ `Inventory` มี 2 คอลัมน์เพิ่ม: `bundle_group` และ `bundle_price`

สินค้าที่มี `bundle_group` **เดียวกัน** จะถูก "รวมจำนวน" กันก่อนคิดราคา ไม่ว่าจะเลือกไซส์ไหนผสมกันก็นับรวม — ทุกๆ ครบ 3 ชิ้นคิดที่ `bundle_price` ส่วนที่เหลือไม่ครบ 3 (0-2 ชิ้น) คิดราคาปกติของสินค้านั้นๆ ต่อชิ้น

ตอนนี้ตั้งไว้ให้ **Ammarit 600ml / Ammarit 1500ml / Ammarit 300ml** (ราคาปกติชิ้นละ 40.-) อยู่กลุ่มเดียวกันชื่อ `ammarit_single` ด้วย `bundle_price = 110`

ตัวอย่าง:
- เลือกรวมกัน 3 ชิ้น (จะไซส์ไหนก็ได้ เช่น เล็ก 1 + กลาง 1 + ใหญ่ 1) → คิด 110.-
- เลือกรวมกัน 6 ชิ้น → คิด 220.-
- เลือกรวมกัน 4 ชิ้น → คิด 110.- (3 ชิ้นแรก) + 40.- (ชิ้นที่เหลือ) = 150.-

ระบบคิดราคานี้ทำงานทั้งฝั่งหน้าเว็บ (ให้เห็นยอดถูกต้องตอนกำลังเลือกสินค้า) และฝั่ง Apps Script (คำนวณยอดจริงตอนบันทึกลงชีต — ยึดฝั่งนี้เป็นหลักเสมอ ต่อให้หน้าเว็บคำนวณผิดก็ไม่กระทบยอดที่บันทึกจริง)

**ถ้า Inventory เดิมของคุณสร้างไว้ก่อนหน้านี้แล้ว** (ยังไม่มีคอลัมน์ bundle_group/bundle_price) ให้เปิด Apps Script แล้วรันฟังก์ชัน `migrateBundlePricing` ครั้งเดียว จะเพิ่มคอลัมน์และตั้งค่าให้ Ammarit ทั้ง 3 ไซส์อัตโนมัติ — ไม่ต้องรัน `setup` ใหม่ (จะไม่กระทบข้อมูลออเดอร์ที่มีอยู่)

อยากเพิ่มสินค้ากลุ่มอื่นเข้าโปรฯ แบบนี้บ้าง ก็แค่ใส่ `bundle_group` ชื่อเดียวกันกับ `bundle_price` ที่ต้องการในแท็บ `Inventory` ได้เลย ไม่ต้องแก้โค้ด

## รูปสินค้า, โลโก้ร้าน, รูปโปรไฟล์ผู้ใช้

### รูปสินค้า (แท็บ `Inventory` คอลัมน์ `image_url`)
ใส่ path หรือ URL รูปสินค้าลงคอลัมน์ `image_url` ของแถวนั้นๆ ในชีต — เว็บจะเอารูปนั้นมาแทนกล่องสีม่วง (ช่องไหนเว้นว่างจะยังเห็นกล่องสีม่วงเหมือนเดิม) วิธีที่ง่ายที่สุดคือ:
1. เพิ่มโฟลเดอร์ `images/products/` ในโปรเจ็ค (ข้าง `index.html`) แล้วใส่ไฟล์รูป เช่น `ammarit600.png`
2. อัพขึ้น GitHub พร้อมไฟล์อื่นๆ
3. ในชีต Inventory ใส่ `images/products/ammarit600.png` ในคอลัมน์ `image_url` ของแถวนั้น

### โลโก้ร้าน (แท็บ `Stores` คอลัมน์ `logo_url`)
วิธีเดียวกัน — สร้างโฟลเดอร์ `images/stores/` ใส่ไฟล์โลโก้ (เช่น `shop_a.png`) อัพขึ้น GitHub แล้วใส่ path นั้นในคอลัมน์ `logo_url` ของร้านนั้นในชีต ถ้าเว้นว่างไว้จะยังเห็นวงกลมสี + emoji แบบเดิม

แนะนำย่อรูปโลโก้/สินค้าให้ไม่เกินประมาณ 500-800px ก่อนอัพ (ไม่จำเป็นต้องเป็น 2000x2000) เพราะรูปที่วางแสดงเป็นวงกลม/กล่องเล็กๆ อยู่แล้ว รูปใหญ่เกินไปแค่ทำให้โหลดช้าบนมือถือโดยไม่ได้ช่วยความคมชัดเพิ่ม ไม่ใช่สาเหตุที่ทำให้รูปไม่ขึ้นเลย (ถ้ารูปไม่ขึ้นเลยมักเป็นเพราะ path/ชื่อไฟล์ไม่ตรง ให้ทดสอบเปิด URL รูปตรงๆ ในเบราว์เซอร์ก่อนเสมอ)

### รูปโปรไฟล์ผู้ใช้ (แท็บ `Users` คอลัมน์ `avatar_url`)
ส่วนนี้ไม่ต้องเข้าไปแก้ชีตเอง — ผู้ใช้อัพโหลดรูปได้เองจากมือถือ:
- ตอนกรอกชื่อครั้งแรก (modal "ยินดีต้อนรับ") มีวงกลม "แตะเพื่อเลือกรูปโปรไฟล์" ให้เลือกรูปจากมือถือได้เลย (ไม่บังคับ)
- หลังใช้งานแล้ว แตะที่รูปวงกลมมุมซ้ายบนหน้าเลือกร้าน (มีไอคอนกล้อง 📷) เพื่อเปลี่ยนรูปได้ตลอดเวลา

รูปจะถูกย่อขนาด/บีบอัดในเบราว์เซอร์ก่อนส่ง (ไม่เกิน ~280px) แล้วบันทึกเป็น **data URI ฝังตรงลงในเซลล์ของคอลัมน์ `avatar_url` เลย** (ไม่ได้อัพโหลดไปเก็บที่ไหนภายนอก)

> **หมายเหตุ (ประวัติการแก้บั๊ก):** ลองมาแล้ว 2 วิธีที่ไม่เวิร์ก — (1) ใช้ลิงก์สาธารณะของ Google Drive แบบ hotlink ตรงๆ (`drive.google.com/thumbnail?...` และ `lh3.googleusercontent.com/d/...`) ทั้งคู่โหลดไม่ขึ้นเวลาฝังเป็น `<img>` ในเว็บนอก Google อย่างเสถียร (2) ให้ Apps Script Web App เสิร์ฟรูปเองผ่าน `doGet` — แต่ Apps Script Web App **ไม่รองรับการ return ไฟล์ binary/Blob ตรงๆ** จาก `doGet` เลย (ขึ้น error "สคริปต์ทำงานเสร็จ แต่ค่าผลลัพธ์ไม่ใช่ประเภทผลลัพธ์ที่สนับสนุน")
>
> วิธีที่ใช้จริงตอนนี้คือฝังรูปเป็น **data URI** ตรงในเซลล์ชีตเลย ไม่ต้องพึ่ง URL ภายนอกใดๆ ทั้งสิ้น เบราว์เซอร์แสดงผลได้ทันทีไม่มี network request แยก จึงไม่มีอะไรที่จะ "โหลดไม่ขึ้น" ได้อีก
>
> ถ้าเคยอัพโหลดรูปโปรไฟล์ไปแล้วตอนที่ยังเป็นโค้ดเก่า (ไม่ว่าจะรูปแบบไหน) รันฟังก์ชัน **`migrateAvatarUrls`** ใน Apps Script ครั้งเดียว — จะไปดึงรูปจาก Google Drive ที่เคยอัพโหลดไว้กลับมาแปลงเป็น data URI ให้อัตโนมัติ โดยไม่ต้องอัพโหลดรูปซ้ำ

**ถ้าชีตเดิมของคุณสร้างไว้ก่อนหน้านี้แล้ว** (ยังไม่มีคอลัมน์ image_url / logo_url / avatar_url) ให้รันฟังก์ชัน `migrateImageColumns` ครั้งเดียวใน Apps Script — จะเพิ่มคอลัมน์ที่ขาดให้ทั้ง 3 แท็บอัตโนมัติ ไม่กระทบข้อมูลเดิม

## บันทึกชื่อ/ที่อยู่ลูกค้าตอนบันทึกออเดอร์ (ทั้ง 2 ร้าน)

กดปุ่ม **บันทึกส่งออเดอร์** แล้วหน้าต่างที่เด้งขึ้นมา (เดียวกับที่ให้เลือกผู้จัดส่ง) จะมีช่อง **ลูกค้า** ให้กรอกชื่อก่อนเสมอ (บังคับ) แล้วค่อยเลือกผู้จัดส่งเพื่อยืนยันบันทึก:

- **พิมพ์ชื่อหรือเบอร์โทร** — ถ้าตรงกับลูกค้าที่เคยบันทึกไว้ในแท็บ `Customers` ระบบจะโชว์รายชื่อให้เลือก พอกดเลือกแล้วจะดึงที่อยู่/เบอร์โทร/หมายเหตุ ของลูกค้าคนนั้นมาแปะให้อัตโนมัติ (กด **เปลี่ยน** เพื่อค้นหาใหม่)
- **ถ้าไม่เจอในระบบ** (ลูกค้าใหม่ หรือแค่ลูกค้าหน้าร้านไม่อยากบันทึกอะไรเพิ่ม) — ใส่แค่ชื่อแล้วกดเลือกผู้จัดส่งเพื่อบันทึกได้เลย ระบบจะไม่เพิ่มชื่อนี้ลงแท็บ `Customers` ให้อัตโนมัติ
- **ถ้าอยากบันทึกที่อยู่ลูกค้าใหม่ไว้ใช้ครั้งหน้า** — กด **"+ เพิ่มที่อยู่ / เบอร์โทร / หมายเหตุ"** จะมีช่องกรอกที่อยู่/เบอร์โทร/หมายเหตุ พร้อมติ๊ก **"บันทึกลูกค้านี้ไว้ใช้ครั้งหน้า"** (ติ๊กไว้เป็นค่าเริ่มต้น) — ถ้าไม่ติ๊ก ข้อมูลที่กรอกจะติดไปกับออเดอร์นี้ใบเดียว แต่จะไม่เข้าแท็บ `Customers`

ข้อมูลลูกค้าที่กรอก/เลือกในแต่ละครั้งจะถูกบันทึกติดไปกับออเดอร์นั้นเสมอ (คอลัมน์ `customer_name`/`customer_phone`/`customer_address`/`customer_note` ในแท็บ `Orders_<store_id>`) เป็น **ค่า ณ เวลาที่บันทึกออเดอร์** — ถ้าลูกค้าย้ายที่อยู่แล้วแก้ในแท็บ `Customers` ภายหลัง ออเดอร์เก่าจะยังโชว์ที่อยู่เดิมตอนที่ส่งจริง ไม่เปลี่ยนตาม

หน้าประวัติออเดอร์ (🧾 ประวัติ) จะโชว์ชื่อลูกค้าต่อท้ายชื่อผู้จัดส่งในแต่ละรายการด้วย ถ้าออเดอร์นั้นมีการระบุชื่อลูกค้าไว้

ถ้าชีตของคุณสร้างไว้ก่อนหน้านี้แล้ว (ยังไม่มีแท็บ `Customers` หรือคอลัมน์ `customer_name`/`customer_phone`/`customer_address`/`customer_note` ในแท็บ Orders) ให้รันฟังก์ชันต่อไปนี้ใน Apps Script ครั้งเดียว (ปลอดภัย รันซ้ำได้ ไม่กระทบข้อมูลเดิม):
- **`migrateCustomersSheet`** — สร้างแท็บ `Customers`
- **`migrateCustomerOrderColumns`** — เพิ่ม 4 คอลัมน์ข้างต้นให้ทุกแท็บ Orders ที่มีอยู่

## รายได้คนส่ง (ร้านผู้ชายขายน้ำเท่านั้น)

ใต้การ์ดโปรไฟล์ในหน้าแรก จะมีกล่องสรุป "รายได้คนส่งที่ยังไม่จ่าย (ผู้ชายขายน้ำ)" แสดงรายชื่อผู้จัดส่งพร้อมยอดคอมมิชชั่น**ที่ยังไม่ได้จ่าย** คำนวณจาก**ออเดอร์ในแท็บ `Orders_shop_a` เท่านั้น** จับคู่ตามชื่อในคอลัมน์ `courier` ของแต่ละออเดอร์ — ไม่กระทบ shop_b หรือส่วนอื่นของระบบเลย ถ้ายังไม่มีออเดอร์ค้างจ่าย กล่องนี้จะซ่อนอัตโนมัติ

**สูตรคำนวณ:** คนส่งได้ **X% ของกำไร** (ราคาขายจริงที่บันทึกไว้ ลบ ต้นทุน) ต่อ 1 รายการสินค้า แล้วรวมทุกออเดอร์ตามชื่อคนส่ง — ใช้ยอด `line_total` ที่บันทึกไว้จริงตอนบันทึกออเดอร์ (ซึ่งคิดโปรฯ Ammarit ครบ 3 ไปแล้วตามราคาปัจจุบัน) ไม่ได้คำนวณราคาขายใหม่

**ปรับ % เองได้ในชีต ไม่ต้องแก้โค้ด:** ค่า % นี้อยู่ในแท็บ **`Settings`** แถว `courier_commission_rate` (คอลัมน์ `setting_value`, ใส่เป็นเศษส่วน เช่น `0.8` = 80%) — แก้เลขในเซลล์นั้นแล้วบันทึก ระบบจะใช้ค่าใหม่ทันทีในการคำนวณครั้งถัดไป ไม่ต้องเปิด Apps Script หรือ deploy ใหม่เลย

ค่าเริ่มต้นตั้งไว้ที่ **0.8 (80%)** ตั้งแต่ปรับราคา Ammarit x3 จาก 110 → 100.-/แพ็ค (2026-09) เพื่อให้คนส่งยังได้ค่าส่งเท่าเดิมคือ **20.-/รอบ** สำหรับแพ็ค Ammarit x3 มาตรฐาน (ราคา 100 − ต้นทุน 75 = กำไร 25, 25 × 0.8 = 20.-) — ถ้าปรับราคาขายหรือต้นทุนอีกในอนาคต แล้วอยากให้ได้ 20.-/รอบเท่าเดิม ให้คำนวณ % ใหม่ด้วยสูตร `20 ÷ กำไรต่อรอบ` แล้วใส่ค่านั้นแทนในแท็บ Settings

ถ้าชีตของคุณสร้างไว้ก่อนหน้านี้แล้ว (ยังไม่มีแท็บ `Settings`) ให้รันฟังก์ชัน **`migrateSettingsSheet`** ใน Apps Script ครั้งเดียว จะสร้างแท็บ Settings พร้อมค่าเริ่มต้น 0.8 ให้อัตโนมัติ (ปลอดภัย รันซ้ำได้ ไม่ทับค่าที่เคยแก้ไว้)

ต้นทุนตั้งไว้ในคอลัมน์ `cost_price` ของแท็บ `Inventory`:
- Ammarit 600ml/1500ml/300ml (เดี่ยว): 25.-/แพ็ค
- Ammarit 600ml/1500ml x3 (แพ็ค 3): 75.-/แพ็ค (25×3)
- Crystal 600ml/1500ml: 43.0588.-/แพ็ค
- Singha และสินค้าอื่นที่ยังไม่ได้บอกต้นทุน: เว้นว่างไว้ **ระบบจะข้ามรายการนั้นไปเลย ไม่นับเป็นกำไร 0** เพื่อไม่ให้ตัวเลขคอมมิชชั่นผิดเพี้ยน — ถ้ามีต้นทุน Singha แล้วใส่เพิ่มในคอลัมน์นี้ได้เลย ระบบจะรวมให้อัตโนมัติในครั้งถัดไป ไม่ต้องแก้โค้ด

ถ้าชีต Inventory ของคุณสร้างไว้ก่อนหน้านี้แล้ว (ยังไม่มีคอลัมน์ `cost_price`) รันฟังก์ชัน **`migrateCostPrices`** ใน Apps Script ครั้งเดียว จะเพิ่มคอลัมน์และใส่ต้นทุน Ammarit/Crystal ให้อัตโนมัติ (ปลอดภัย รันซ้ำได้ ไม่กระทบข้อมูลอื่น)

### จ่ายค่าส่งแล้ว / รีเซ็ตยอด

ข้าง "จ่ายแล้ว/รีเซ็ต" ในแต่ละแถวของกล่องรายได้คนส่ง — กดแล้วยืนยัน ระบบจะทำเครื่องหมายออเดอร์ที่ยังไม่จ่ายทั้งหมดของคนส่งคนนั้น (เฉพาะ shop_a) ว่า "จ่ายแล้ว" (คอลัมน์ `commission_paid` ในแท็บ `Orders_shop_a`) ยอดคงเหลือของคนส่งคนนั้นจะกลับเป็น 0.- ทันที และเริ่มสะสมใหม่จากออเดอร์ถัดไป

**ข้อมูลออเดอร์เก่าไม่ได้ถูกลบทิ้งเลย** — แค่ทำเครื่องหมาย ยังเปิดดูประวัติ/ยอดขายจริงย้อนหลังในชีตได้ตามปกติ แค่จะไม่ถูกนับรวมในยอด "ที่ยังไม่จ่าย" อีก

ถ้าชีต Orders_shop_a (หรือ Orders_shop_b) ของคุณสร้างไว้ก่อนหน้านี้แล้ว (ยังไม่มีคอลัมน์ `commission_paid`) ให้รันฟังก์ชัน **`migrateCommissionPaidColumn`** ใน Apps Script ครั้งเดียว จะเพิ่มคอลัมน์ให้ทุกแท็บ Orders ที่มีอยู่อัตโนมัติ

## เว็บที่ Add to Home Screen ไว้จะอัพเดทเองได้แล้ว

ก่อนหน้านี้ถ้าแก้เว็บแล้วไม่ลบไอคอนแอปแล้วติดตั้งใหม่ หน้าจะไม่เปลี่ยน — แก้แล้วให้อัพเดทอัตโนมัติ: ทุกครั้งที่เปิดแอป (จากไอคอนที่ติดตั้งไว้ หรือ browser ปกติ) เบราว์เซอร์จะเช็ค `sw.js` เบื้องหลังว่ามีเวอร์ชันใหม่ไหม ถ้ามีจะโหลดของใหม่มาติดตั้งและรีเฟรชหน้าให้เองอัตโนมัติ 1 ครั้ง (อาจเห็นหน้าสะดุด/รีเฟรชแวบเดียวตอนเปิดแอปครั้งแรกหลังมีอัพเดท)

**เงื่อนไขสำคัญที่ยังต้องทำอยู่:** ทุกครั้งที่แก้ไฟล์หน้าเว็บ (`index.html`/`style.css`/`app.js`) ต้องแก้เลข `CACHE_NAME` ใน `sw.js` ให้เปลี่ยนไปด้วยเสมอ (เช่น v5 → v6) เพราะเป็นตัวกระตุ้นให้เบราว์เซอร์รู้ว่ามีของใหม่ — ถ้าใครแก้โค้ดเองในอนาคตแล้วลืมขั้นตอนนี้ ระบบอัพเดทอัตโนมัติจะไม่ทำงาน (ผมจะจำขั้นตอนนี้ให้เองทุกครั้งที่แก้โค้ดให้)
